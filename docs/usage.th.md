### กราฟ

- หนึ่ง **hub** ต่อหนึ่ง `session` มี `sub-agent` โคจรรอบ
- `sub-agent` ชั้นลึก **โคจรรอบตัวที่ spawn มันจริง ๆ** ไม่ใช่รอบ `session` ⇒ กลุ่มพ่อ–ลูกอ่านเป็นก้อนเดียว
  leash หดชั้นละ 0.6 เท่า พื้น 26px
- ป้ายใต้โหนดคือ tool ที่กำลังรันอยู่ตอนนี้และรันมานานแค่ไหน · วงรอบโหนดจะแดงตามสัดส่วน tool ที่ล้มเหลว
- ลากโหนดเพื่อหมุดไว้ · ลากพื้นหลังเพื่อเลื่อน · ล้อเมาส์เพื่อซูม · `รีเซ็ตมุมมอง` ปลดหมุดทั้งหมดและจัดกรอบใหม่

### คอนโทรล

| คอนโทรล | ทำอะไร |
| --- | --- |
| `กรอง ชื่อ/โปรเจกต์…` | ช่องกรอง — จับทั้งชื่อ `session` และ path ของโปรเจกต์ |
| `☐ เตือนซ้ำเมื่อรอฉัน` | เตือนสถานะที่รอคำตอบ/การยืนยันซ้ำจนกว่าสถานะรอจะหายไป |
| `เสียง AI — ปิด / เอฟเฟกต์ / พูด+เอฟเฟกต์` | เลือกปิด ใช้เฉพาะเอฟเฟกต์ หรือใช้เสียงพูดภาษาไทยพร้อมเอฟเฟกต์ |
| `รีเซ็ตมุมมอง` | คืนซูม/การเลื่อน และปลดหมุดโหนดที่ลากไว้ |
| `NEURAL CORE` · `PIXEL OFFICE` | ท้ายแถบหัว: สลับไปหน้า 3 มิติ หรือออฟฟิศพิกเซล (สตรีมเดียวกัน ไม่ต้องรีสตาร์ตอะไร) |
| คลิกโหนด | เปิดแผงข้างของ `session` หรือ `sub-agent` ตัวนั้น |
| คลิกแถวในแผง | กางออก (tool input เต็ม ข้อความ error จริง เหตุผลที่ถูก deny) |
| คลิกแถวในตาราง waste | เจาะลงไปในหมวด error นั้น |
| `← กลับไปตารางหมวด` | ถอยกลับจากหน้าเจาะ |
| `✕` | ปิดแผงข้าง |

**คีย์บอร์ด:** `Enter` หรือ `Space` บนโหนดที่โฟกัสอยู่ = เปิดแผง · `Escape` = ปิดแผง
มีเพียงโหมดเสียงและค่า `เตือนซ้ำเมื่อรอฉัน` ที่ถูกจำข้ามการรีเฟรช ข้อมูลกิจกรรมและ transcript
ไม่ถูกเก็บลงเบราว์เซอร์

audio engine ชุดเดียวกันทำงานทั้งสามหน้า (Classic · NEURAL CORE · PIXEL OFFICE) โดยมี 3 โหมด `ปิด` เป็นค่าเริ่มต้นและ
เงียบทั้งหมด · `เอฟเฟกต์` เล่นเฉพาะเสียงสัญญาณ · `พูด+เอฟเฟกต์` เพิ่มคำพูดภาษาไทยสั้น ๆ หลังผู้ใช้คลิก
เริ่มเสียงตามกฎของเบราว์เซอร์ event ใหม่ทุกตัวมี cue ที่จำแนกตระกูลเหตุการณ์ได้พร้อมความต่างเล็กน้อย
ส่วนเสียงพูดใช้เฉพาะตอนเปลี่ยนสถานะสำคัญและสรุป event ที่มารัวเป็นชุด ประโยคจะหมุนหลายแบบโดยไม่ใช้
ประโยคเดิมติดกัน และเลือกคำทั่วไปอย่าง `ผู้ช่วย` แทนศัพท์เทคนิคที่ฟังแล้วเข้าใจยาก

เมื่อเปิด `เตือนซ้ำเมื่อรอฉัน` ระบบจะเตือนทันทีเมื่อเข้าสู่สถานะรอผู้ใช้ ส่งเอฟเฟกต์ซ้ำเมื่อครบประมาณ 30 วินาที
เพิ่มคำพูดเมื่อครบประมาณ 90 วินาทีถ้าใช้โหมด `พูด+เอฟเฟกต์` แล้วเตือนทุกประมาณ 120 วินาทีจนกว่าสถานะรอจะหายไป
(เบราว์เซอร์อาจหน่วงเวลาเมื่อแท็บอยู่เบื้องหลังหรือเครื่องพัก) ถ้ามีหลายงาน
รอพร้อมกันจะรวมเป็นข้อความเดียว ค่านี้ยังถูกจำไว้ขณะปิดเสียง แต่จะไม่ส่งเสียงจนกว่าจะเลือกโหมดที่มีเสียง

snapshot ที่ส่งซ้ำจะไม่ทำให้เสียงซ้ำ และ snapshot แรกใช้เป็น baseline แบบเงียบ จึงไม่อ่านประวัติเก่า
เอฟเฟกต์ถูกสร้างในเครื่องด้วย Web Audio ส่วนคำพูดเลือก voice `th-*` ที่ติดตั้งอยู่และเบราว์เซอร์เปิดให้ใช้
ผ่าน Web Speech บน Windows, macOS หรือระบบปฏิบัติการอื่นที่รองรับก่อน ถ้าไม่มีเสียงไทย ระบบจะใช้เสียง
เริ่มต้นของเครื่องพูดข้อความชุดเดียวกันเป็นภาษาอังกฤษแทน (tooltip ของปุ่มจะบอกว่ากำลังใช้เสียงไหน) และ
ถ้าไม่มีเสียง local เลยจึงถอยไปใช้เอฟเฟกต์อย่างปลอดภัย เส้นทางเสียงไม่ส่งข้อความหรือข้อมูลกิจกรรมออกทางเครือข่าย

### แท็บในแผงข้าง

`session` ได้ 5 แท็บ:

| แท็บ | มีอะไร |
| --- | --- |
| `บทสนทนา` | ฟีดเหตุการณ์ — คำสั่งของผู้ใช้ การคิด การเรียก tool error การถูก deny |
| `💸 error กิน token` | หมวดของ error เรียงตามโทเค็นที่เสียไปกับการแก้ตัว พร้อมวิธีแก้บรรทัดเดียวและหน้าเจาะรายการจริง |
| `รายละเอียด session` | `sessionId`, ชื่อ, หัวข้อ, surface, ชนิด, สถานะ, `endedBy`, cwd, branch, model, effort, pid, version, เวลาเริ่ม, ล่าสุด, ยอด tool/error/deny, พบ `transcript` หรือไม่ |
| `sub-agent ที่จบแล้ว` | ต้นไม้เรียงแบบ DFS (พ่อก่อนลูกเสมอ · เยื้อง 16px ต่อชั้น · ขีดต่อ `└`) |
| `tool / error / deny` | ทุกการเรียก tool ทุก error และทุกการ deny ของ `session` นี้ |

`sub-agent` ได้ 3 แท็บ: `tool ทั้งหมด` · `รายละเอียด` (มีแถว **พ่อ** ชี้กลับไปที่ตัวที่ spawn มัน) และแท็บ waste

> แท็บ `💸 error กิน token` เป็นตัวที่ไม่เหมือนใคร — มันไล่ต้นทุนของ **request ที่ต้องยิงใหม่**
> กลับไปหา error ตัวที่เป็นต้นเหตุ ทำให้เห็นว่า (ตัวอย่างเช่น) guard hook ที่บล็อก tool แพงกว่า
> ความผิดพลาดที่มันกันไว้ หมวดต่าง ๆ มาจาก `lib/tool-error-kinds.cjs`

## NEURAL CORE (หน้า 3 มิติ)

### ผังหน้าจอ

```
┌────────────────────────────────────────────────────────────────────────────┐
│ NEURAL CORE                          FPS  SESS  SUB-AGENT  TOOL  ERR  DENY │
│ ● mood word                          163   3      27/34     17    1    0  ◔│
├──────────────┐                                                             │
│ เซสชัน    ‹  │                                                             │
│ ● harbor-09  │                    (the brain + orbiting agents)            │
│ ● forge-66   │                                                             │
│              │                                          ┌──────────────────┤
└──────────────┘                                          │ detail panel     │
┌───────────────────────────────────────────┐ ┌────────────┴──────────────────┤
│ ฟีดสด (live feed, 60 rows)  [หยุดเลื่อน]  │ │ quality · auto-rotate · reset │
└───────────────────────────────────────────┘ └───────────────────────────────┘
```

### มันแสดงอะไร

- **แกนกลาง** คือ `session` สีของมันและคำบอกอารมณ์มุมซ้ายบนเดินตามสถานะ: กำลังคิด · กำลังเรียก tool ·
  กำลังทำงานผ่าน sub-agent · รออนุญาต · กำลังแตก agent · ถูกบล็อก · ว่าง
- **แสงที่โคจรรอบ** แต่ละดวงคือ `sub-agent` หนึ่งตัว เส้นเชื่อมลากตรงไปหาพ่อจริงของมัน
- **มาตรวัด** คือ FPS, จำนวน `session`, `sub-agent` (`ที่วิ่ง/ทั้งหมด`), tool, error, deny และวงแหวนโควตา ·
  วงแหวนโควตาจะซ่อนตัวเองเมื่อไม่มีข้อมูลโควตาเลย
- **ฟีดสด** ด้านล่างเก็บไว้ 60 แถวล่าสุด

### คอนโทรล

| คอนโทรล | ทำอะไร |
| --- | --- |
| `‹` / `›` | ย่อ / ขยายรางรายชื่อ `session` |
| `หยุดเลื่อน` / `เลื่อนต่อ` | หยุด / เลื่อนตามฟีดต่อ |
| `โฟกัสกล้อง` | พากล้องไปที่โหนดที่เลือกไว้ |
| `คุณภาพ: ต่ำ / กลาง / สูง` | คุณภาพการเรนเดอร์ |
| `หมุนอัตโนมัติ: เปิด / ปิด` | หมุนเองอัตโนมัติ — ค่าเริ่มต้นคือ **ปิด** |
| `รีเซ็ตกล้อง` | คืนกล้อง (การหมุนและจุดเล็ง — ดูหมายเหตุด้านล่าง) |
| `เสียง AI — ปิด / เอฟเฟกต์ / พูด+เอฟเฟกต์` | เลือกโหมดเสียงชุดเดียวกัน โดยแกนสมองจะ pulse ตาม cue และคำพูด |
| `เตือนซ้ำเมื่อรอฉัน: เปิด / ปิด` | เปิดหรือปิดการเตือนซ้ำขณะรอคำตอบจากเรา |
| `ทดสอบฉาก` | dropdown เลือกฉาก — **โผล่เฉพาะใน fixture mode** |
| `← หน้าคลาสสิก` | กลับหน้าคลาสสิก |
| `PIXEL OFFICE` | สลับไปหน้าออฟฟิศพิกเซล |

**เมาส์:** ลากซ้าย = orbit · ลากขวา (หรือ `Shift` + ลากซ้าย) = pan · ล้อ = ซูม · สองนิ้ว = pan และ pinch
มีโมเมนตัม ปล่อยแล้วยังไถลต่อ · คลิกภายในระยะ 6px จากโหนด = เลือกโหนดนั้นและโฟกัสกล้องไปที่มัน

**คีย์บอร์ด:** `Escape` = ยกเลิกการเลือก · `Space` = สลับหมุนอัตโนมัติ มีแค่สองปุ่มนี้

> ถ้าซูมออกไปไกลแล้วกด `รีเซ็ตกล้อง` การจัดกรอบจะกลับมา แต่ระยะซูมอาจไม่กลับ
> ให้รีเฟรชหน้าถ้าต้องการกล้องค่าเริ่มต้นแบบชัวร์ ๆ

> ถ้าเบราว์เซอร์เปิด WebGL ไม่ได้ จะมีข้อความบอกพร้อมลิงก์กลับหน้าคลาสสิก · และมีตัวเฝ้าที่จะเตือน
> ถ้าเฟรมแรกยังไม่มาภายใน 12 วินาที — ลอง `?quality=low`

## PIXEL OFFICE (หน้าพิกเซล)

ออฟฟิศพิกเซลอาร์ต 2 มิติที่เล่าข้อมูลชุดเดียวกันเป็นเรื่องราว ทุก `session` คือ **ห้อง** หนึ่งห้อง agent หลักคือ **หัวหน้า**
และ `sub-agent` ทุกตัวที่ยังทำงานอยู่คือ **ผู้ช่วย** หนึ่งคน ตัวละครเดินไปยังสถานีที่ตรงกับ tool ที่รันอยู่จริง ⇒ ดูจากตำแหน่ง
ที่ยืนก็รู้ว่าใครกำลังอ่าน ค้นหา รันคำสั่ง หรือรอคุณอยู่ · ใช้ Canvas 2D ล้วน (ไม่ต้องมี WebGL) และภาพทุกชิ้นวาดด้วยโค้ด
⇒ ไม่มีไฟล์ภาพ ไม่มีอะไรต้องโหลดเพิ่ม

### ผังหน้าจอ

```

│                [audio mode ▾] [☐ repeat reminders]  [classic] [NEURAL CORE]│
├──────────────────────────────────────────────────┬─────────────────────────┤
│  OP  my-project  thinking    ← room nameplate    │ [−] ×2 [+] [fit]        │
│ ┌──────────────────────────────────────────────┐ │ [captions: auto] [?]    │
│ │ door · stations along the back wall · phone  │ ├─────────────────────────┤
│ │ ▭ ▭ ▭ ▭ ▭  helper desks        lead's corner │ │ detail panel            │
│ │ ▭ ▭ ▭ ▭ ▭                      rug · couch   │ │ (click a character)     │
│ └──────────────────────────────────────────────┘ ├─────────────────────────┤
├───────────────────────────────────┐              │ ห้อง (room list)         │
│ event log (60 rows, click a row)  │              │                         │
└───────────────────────────────────┴──────────────┴─────────────────────────┘
```

บนจอแคบ (≤ 760px) ชิปสรุปและตัวควบคุมเสียงถูกพับไว้หลังปุ่ม `สรุป ▾` (ปุ่มยังบอกจำนวนงานที่รอคุณอยู่) · บันทึกเหตุการณ์
และรายชื่อห้องเริ่มแบบพับ · แผงรายละเอียดกลายเป็น bottom sheet

### ออฟฟิศ

- **หนึ่ง `session` = หนึ่งห้อง** จัดเป็นตารางตามพื้นที่ที่แผง HUD ไม่ได้บัง (3–4 ห้องบนจอ 1440×900 ออกมาเป็น 2×2) ·
  ห้องอยู่ที่เดิมเสมอ — ห้องใหม่ถูกเพิ่มเข้ามา ห้องเดิมไม่ถูกสลับที่
- **ป้ายชื่อห้อง** ลอยเหนือห้อง: ชิปรุ่นโมเดล · ชื่อห้อง (title → name → ชื่อโฟลเดอร์โปรเจกต์ → 8 ตัวแรกของ `sessionId`) ·
  สถานะคำเดียว (`ทำงาน` `คุมงาน` `รอคุณ` `คิด` `ติดด่าน` `ว่าง` `ไม่ทราบ` `ปิดแล้ว`) · ซูม ×2 ขึ้นไปมีโฟลเดอร์โปรเจกต์
  · branch · surface ต่อท้ายถ้าที่พอ · ที่ซูม ×1 ซึ่งป้ายเหนือหัวถูกซ่อน ป้ายชื่อห้องจะบอกแทนว่าหัวหน้ากำลังทำอะไร พร้อม
  `· ผู้ช่วย N` (ผู้ช่วยที่ทำงานอยู่ N คน) · คลิกป้ายชื่อ = ไปที่ห้องนั้น
- **ผนังหลัง** เรียงจากซ้ายไปขวา: ประตู · ตู้จดหมาย · ชั้นหนังสือ · ตู้เอกสาร · เทอร์มินัล · ไวต์บอร์ด · ตู้เว็บ · แผงเครื่องมือ ·
  เครื่องพิมพ์ · เครื่องกาแฟ · กล้องวงจรปิด · ตู้โทรศัพท์ · **ป้ายคะแนน**บนผนังบอก ผู้ช่วยที่จบแล้ว/ทั้งหมด ของ `session`
  และเปลี่ยนเป็นสีส้มเมื่อมีตัวที่ล้มเหลว
- **มุมหัวหน้า** อยู่ทางขวา: โต๊ะใหญ่ พรม โซฟา · **โต๊ะผู้ช่วย** เรียงแถวละ 5 ตัว ห้องโต/หดทีละ 10 โต๊ะ และห้องที่ใหญ่มาก
  มีประตูข้างเพิ่มในผนังซ้าย ผู้ช่วยจะได้ไม่ต้องไปต่อคิวประตูเดียว
- **`session` ที่ปิดแล้ว** ห้องยังอยู่แต่ไฟดับ มีป้าย `ปิดแล้ว · N นาทีก่อน` ค้างไว้ตาม `--stale-minutes` (ค่าเริ่มต้น 30)
  เท่ากับหน้าอื่นทุกประการ

### ตัวละคร

- **หัวหน้า** ผูกเนกไท + ใส่เฮดเซ็ต · **ผู้ช่วย** ได้แว่น หมวกแก๊ป หูฟัง หรือหมวกไหมพรมตามชนิดของ agent ⇒ ผู้ช่วยชนิดเดียวกัน
  แต่งตัวเหมือนกัน
- **agent ตัวเดิมหน้าตาเดิมเสมอ** สีผิว สีผม ทรงผม คำนวณจาก id ⇒ ตามดูตัวละครตัวเดียวไปรอบห้องได้ และรีเฟรชแล้วก็ยังหน้าเดิม
- **สีเสื้อ = โมเดล:**

| สีเสื้อ | แท็ก | โมเดล |
| --- | --- | --- |
| เขียว | `HA` | Haiku |
| น้ำเงิน | `SO` | Sonnet |
| ม่วง | `OP` | Opus |
| ส้ม | `FA` | Fable |
| เทา | — | ไม่ทราบรุ่น (ใน `transcript` ยังไม่มีข้อความตอบจากโมเดล) |

เฉพาะ `sub-agent` ที่ **กำลังวิ่ง** เท่านั้นที่กลายเป็นตัวละคร · ตัวที่จบไปแล้วตั้งแต่ครั้งแรกที่หน้าเห็นจะไม่ถูกวาด นับแค่บนป้ายคะแนน

### สถานี — tool แต่ละตัวทำที่ไหน

| สถานี | tool | ภาพที่เห็น |
| --- | --- | --- |
| 📚 ชั้นหนังสือ | `Read` | ยืนอ่านหนังสือ |
| 🗄️ ตู้เอกสาร | `Grep`, `Glob` | เอื้อมค้นในลิ้นชัก |
| 🖥️ เทอร์มินัล | `Bash`, `PowerShell` | ยืนพิมพ์ |
| ✏️ โต๊ะของตัวเอง | `Edit`, `MultiEdit`, `NotebookEdit`, `Write` — และ tool อื่นทุกตัวที่ไม่อยู่ในตารางนี้ | นั่งพิมพ์ |
| 🌐 ตู้เว็บ | `WebFetch`, `WebSearch` | ยืนพิมพ์ที่ตู้ |
| 📋 ไวต์บอร์ด | `TodoWrite`, `Workflow` | เขียนกระดาน |
| 🧰 แผงเครื่องมือ | `Skill`, `ToolSearch`, `mcp__*` ทุกตัว | หยิบเครื่องมือ / เสียบปลั๊กอิน |
| 📹 กล้องวงจรปิด | `Monitor` | ยืนใต้กล้อง เงยหน้ามอง |
| 🖨️ เครื่องพิมพ์ | `Artifact` | ยืนที่เครื่องพิมพ์ |
| ☎️ ตู้โทรศัพท์ | `AskUserQuestion` | ถือหูโทรศัพท์ |
| 🤖 เดินคุมงาน | `Agent`, `Task` | หัวหน้าเดินตรวจโต๊ะผู้ช่วย · ผู้ช่วยที่จ้างผู้ช่วยต่อจะยืนคุมข้างโต๊ะตัวเอง |

หัวหน้าไปที่สถานีของ **tool ตัวแรกที่กำลังรันซึ่งไม่ใช่ `Agent`/`Task` หรือ `AskUserQuestion`** · สถานะอื่น ๆ หัวหน้าอยู่ตรงนี้:

| สถานะ `session` | หัวหน้าอยู่ไหน | สัญญาณ |
| --- | --- | --- |
| ⚙️ tool | สถานีของ tool นั้น | ป้าย: tool · เป้าหมาย · นาฬิกา |
| 🤖 delegating | เดินตรวจโต๊ะผู้ช่วยของตัวเอง 2–3 โต๊ะ หยุดดูทีละโต๊ะ | `สั่งงานผู้ช่วย · ทำงานอยู่ N คน` |
| 🙋 waiting — ถามคำถาม | ตู้โทรศัพท์ ถือหูโทรศัพท์ | ❓ กระพริบ โทรศัพท์ดัง |
| 🙋 waiting — รออนุญาต | ตู้โทรศัพท์ ยกมือ | ❗ กระพริบ |
| 💭 thinking | ไวต์บอร์ด สลับเขียนกระดานกับยืนคิด | ลูกโป่งความคิด · 💡 แวบหนึ่งเมื่อมีบล็อก thinking เข้ามา |
| ⛔ blocked | นั่งฟุบที่โต๊ะ | เมฆฝนเหนือหัว + ⚠️ ข้างหัว |
| 😴 idle | เครื่องกาแฟ · ว่างเกิน 45 วินาทีจะไปงีบบนโซฟา | ☕ แล้วค่อย Zzz |
| ปิดแล้ว | เดินออกประตู แล้วไฟห้องดับ | ป้าย `ปิดแล้ว · N นาทีก่อน` |

**ผู้ช่วยไม่วิ่งข้ามห้องทุกครั้งที่เรียก tool** — tool ของผู้ช่วยเปลี่ยนทุกสองสามวินาที แต่เดินจากโต๊ะแถวหลังอาจใช้หลายวินาที
ผู้ช่วยจึงลุกเฉพาะเมื่อ "น่าจะไปทัน": สถานีอยู่ใกล้ไม่เกิน 8 ช่อง หรือ tool รันมานานพอจะคุ้มเดินแล้ว · ไม่งั้นทำงานของสถานีนั้น
ที่โต๊ะตัวเอง พร้อมไอคอนสถานีในลูกโป่งความคิด · สถานีหนึ่งรับคนทำงาน/ต่อคิวได้สูงสุด 3 คน ที่เหลือทำที่โต๊ะแบบเดียวกัน ·
ผู้ช่วยที่ไม่มี tool รันอยู่ = นั่งคิดที่โต๊ะ

### เนื้อเรื่อง

- **คำสั่งใหม่มาถึง** เป็นจดหมายลอยจากประตูเข้าตู้จดหมาย หัวหน้าเดินไปเปิดอ่าน ระหว่างนั้นมีบรรทัด `📬 คำสั่งใหม่: "…"`
  พร้อมข้อความคำสั่งจริงซ้อนเหนือป้ายงาน
- **ผู้ช่วยที่ถูกจ้างเดินเข้าประตู** (ห้องใหญ่ใช้ประตูที่ใกล้โต๊ะตัวเองที่สุด) ทยอยเข้าทีละไม่กี่คน แล้วนั่งโต๊ะที่ว่าง
- **error** ทำให้ตัวละครสะดุ้ง มีประกายไฟที่สถานี (ที่เทอร์มินัลเป็นควัน) · ถูกปฏิเสธจะมีตราประทับสีแดงเพิ่ม
- **ผู้ช่วยที่จบงานดีใจ** (มีประกาย) หรือ **เสียใจ**เมื่อล้มเหลว (มีเมฆฝนเล็ก ๆ) แล้วถือรายงานไปส่ง **ผู้ว่าจ้าง** — หัวหน้า
  หรือผู้ช่วยที่จ้างมันมา — ผู้ว่าจ้างตอบด้วยหัวใจหรือ ✓ (หรือ ✗ ถ้างานล้มเหลว) แล้วผู้ช่วยเดินออกประตู · ถ้าผู้ว่าจ้างอยู่ไกล
  หรือห้องเต็มและมีผู้ช่วยรอเข้าห้องอยู่ จะยื่นรายงานจากที่ยืน (กระดาษลอยข้ามห้องไป) แล้วปุ๊ฟหาย · ผู้ช่วยที่ถูกหยุดกลางทาง
  เดินออกไปเฉย ๆ
- **สิ่งที่ agent พูด** (ข้อความตอบสั้น ๆ) ขึ้นเป็นฟองคำพูดเหนือหัวสองสามวินาที · ทุกครั้งที่ audio engine เล่น cue หรือพูด
  ตัวละครของเหตุการณ์นั้น (หรือหัวหน้าห้อง) จะขยับปากตาม
- **`session` จบ**: หัวหน้าเดินออกประตู แล้วไฟห้องดับ

snapshot แรกเป็น baseline แบบเงียบเหมือนระบบเสียง: ทุกคนถูกวางที่จุดของตัวเองทันที ไม่มีการเดินเข้า ไม่มีบรรทัดเล่าเรื่อง —
มีแค่บรรทัด `💡 เปิดไฟออฟฟิศ: …` ในบันทึกเหตุการณ์ · หลังจากนั้นทุกฉากถูกเล่าในบันทึกเหตุการณ์บรรทัดละเรื่อง และเหตุการณ์
ที่มาเป็นชุด (พายุงานจบพร้อมกันหลายสิบตัว) ถูกรวมเป็นบรรทัดเดียวต่อห้อง

### ป้ายงาน — ซื่อตรงโดยการออกแบบ

- ป้ายงาน **บอก tool หรือสถานะจริงล่าสุดจาก snapshot เสมอ** พร้อมนาฬิกา เช่น `📖 อ่าน server.mjs 0:12` · ภาพอาจช้ากว่า
  ข้อมูลนิดหน่อย (คนต้องเดิน) แต่ป้ายไม่ช้า
- tool ที่ **เริ่มและจบระหว่างสอง poll** (~700 ms) ไม่เคยถูกเห็นว่ากำลังรัน · ระหว่างที่หัวหน้ากำลังคิด ออฟฟิศอาจ **เล่าย้อน** มัน
  (หัวหน้าเดินแวบไปที่สถานีนั้น) แต่ป้ายจะขึ้นว่า `✓ เมื่อกี้ · …` และแผงรายละเอียดติดป้าย `ภาพย้อนหลัง` · สถานะจริงชนะเสมอ:
  ทันทีที่หัวหน้าไม่ได้กำลังคิดแล้ว การเล่าย้อนถูกทิ้ง
- **โหมดป้าย** (ปุ่ม `ป้าย:`): `อัตโนมัติ` = ป้ายของหัวหน้าขึ้นเมื่อซูม ×2 ขึ้นไป ของผู้ช่วยขึ้นเมื่อเลือก/ชี้ หรือซูม ×4
  (×4 เป็นชิปไอคอน ข้อความเต็มที่ ×5 ขึ้นไป) · `ทั้งหมด` = ขึ้นทุกป้าย · `ปิด` = ซ่อนทั้งหมด · ป้ายหลบกันเองไม่ทับหน้าใคร —
  ตัวที่เลือก/ชี้อยู่ชนะเสมอ

### กล้อง

กล้อง **ขยับเฉพาะตอนคุณสั่ง** — ลาก · ล้อเมาส์ · `−`/`+` · `จัดกรอบ` · ลูกศร · หรือคลิกสิ่งที่แปลว่า "ไปที่นั่น" (ห้องในรายชื่อ
ป้ายชื่อห้อง แถวในบันทึกเหตุการณ์ ดับเบิลคลิกตัวละคร) · ข้อยกเว้นเดียวคือจัดกรอบอัตโนมัติ **ครั้งเดียว** ตอนข้อมูลชุดแรกที่มีห้อง
มาถึง · ห้องใหม่ที่เกิดนอกจอได้ toast (ไม่ถี่กว่า 45 วินาทีครั้ง) ไม่ใช่กล้องเลื่อนไปหา

ถ้าห้องที่ **รอคุณหรือติดด่าน** มีหัวหน้าอยู่นอกส่วนที่มองเห็น (นอกจอ หรือถูกแผงบัง) จะมีป้ายเล็กชิดขอบพื้นที่ที่มองเห็นชี้ไปหา
ห้องนั้น และแถวของห้องในรายชื่อ `ห้อง` กระพริบ · คลิกอันไหนก็ได้เพื่อไปที่ห้อง

ซูมเป็นขั้นจำนวนเต็ม ×1 ถึง ×8 ⇒ พิกเซลทุกจุดของภาพเป็นสี่เหลี่ยมคมเสมอ

| `✕` | ปิดแผงรายละเอียด |

**คีย์บอร์ด:** `+` = ซูมเข้า · `-` = ซูมออก · `0` = จัดกรอบ · ลูกศร = เลื่อน (กด `Shift` ค้างเพื่อเลื่อนทีละมาก) · `Esc` ปิด
คำอธิบายฉากก่อน แล้วค่อยปิดแผงรายละเอียด · ระหว่างพิมพ์ในช่องข้อความหรือเลือก dropdown ปุ่มพวกนี้ไม่ทำงาน

**จอสัมผัส:** นิ้วเดียว = เลื่อน · แตะ = เลือก · บีบนิ้ว = ซูมทีละขั้น

### แผงรายละเอียด

ทุกบรรทัดในแผงมาจาก **snapshot ล่าสุด** ไม่ใช่จากท่าที่ตัวละครกำลังเล่นอยู่:

- **หัวแผง:** `หัวหน้า` / `ผู้ช่วย` · ชื่อ · มาจากไหน (surface + ชนิดสำหรับหัวหน้า · ชนิด agent + ห้องสำหรับผู้ช่วย) ·
  ชิปโมเดล · ชิปสถานะพร้อมนาฬิกาเดินสด
- **`กำลังทำ`**: tool ทุกตัวที่กำลังรัน แต่ละตัวมีนาฬิกาของตัวเอง (สูงสุด 6 แถว แล้วตามด้วย `และอีก N รายการ`) · ผู้ช่วยที่จบแล้ว
  เป็น `งานล่าสุด` พร้อม ✓/✗ และเวลาที่ใช้
- **`บนจอตอนนี้:`** — สิ่งที่ตัวละครกำลังเล่นอยู่ ถ้าเป็นการเล่าย้อนจะติดชิป `ภาพย้อนหลัง` ⇒ แยกเรื่องเล่าออกจากข้อเท็จจริง
  ด้านบนได้เสมอ
- **ตัวนับ 4 ช่อง:** tool · error · `ถูกปฏิเสธ` · `โทเค็น` สำหรับหัวหน้า · tool · error · `เวลา` (นับจากตอนถูกจ้าง) · โทเค็น
  สำหรับผู้ช่วย
- **ข้อความ:** หัวหน้าแสดงคำสั่งล่าสุดจากคุณ · สิ่งที่พูดล่าสุด · สะดุดล่าสุด (error / ถูกปฏิเสธ / ถูกบล็อก) · ผู้ช่วยแสดง
  งานที่ได้รับ · สิ่งที่พูดล่าสุด · สะดุดล่าสุด · และรายงานที่ส่งเมื่อจบแล้ว
- **ข้อเท็จจริง:** `ผู้ว่าจ้าง` (คลิกเพื่อไล่สายการจ้างขึ้นไปทีละขั้น) · ลำดับชั้น · โปรเจกต์ + branch · surface + version ·
  model + effort · ผู้ช่วย (ทำงาน/จบ/พลาด/รวม) · `ตัดสินสถานะจาก` (หลักฐานที่ server ใช้ตัดสินว่าผู้ช่วยยังทำงาน —
  พิสูจน์แล้วหรืออนุมานเอา) · ผลลัพธ์ · `จบเทิร์นด้วย` · เริ่มเมื่อ · workflow id
- **`ดูละเอียดในหน้าคลาสสิก →`** — tool history เต็ม หมวด error และ input ดิบอยู่ในหน้าคลาสสิก · หน้า pixel ไม่เคยเรียก
  `/api/agent` เลย ใช้แค่ข้อมูลจาก stream

ตัวละครที่เลือกไว้จบงานแล้วเดินออกไป ⇒ แผงปิดเอง

> การเคลื่อนไหว: ถ้าตั้ง `prefers-reduced-motion` ไว้ อนุภาคระเบิด การโยกตัว และการสั่นจะถูกปิด ฟองเตือนติดนิ่งแทนการ
> กระพริบ · ค่านี้อ่านครั้งเดียวตอนเปิดหน้า

> ถ้า `/activity-audio.js` โหลดไม่ขึ้น หน้ายังทำงานต่อได้ และตัวควบคุมเสียงขึ้นว่า `เสียง AI: ไม่รองรับ` · ถ้าไฟล์อื่นโหลด
> ไม่ขึ้นจะมีการ์ด error พร้อมลิงก์กลับหน้าคลาสสิก · และมีตัวเฝ้าที่จะเตือนถ้าเฟรมแรกยังไม่มาภายใน 12 วินาที

## ความหมายของสถานะ

กฎที่เครื่องมือนี้ยึดทั้งตัวคือ *อย่ามั่นใจเกินหลักฐาน* และความเงียบ **ไม่ถูกนับ**ว่าเป็นปัญหา
เพราะการเงียบนาน ๆ คือลายเซ็นปกติของการคิด

| สถานะ | หลักฐาน |
| --- | --- |
| ⚙️ tool | มี `tool_use` ที่ยังไม่มี `tool_result` คู่กัน |
| 🤖 delegating | call ที่ค้างอยู่เป็น `Agent`/`Task` → parent กำลังรอผลจาก sub-agent |
| 🙋 waiting | มี `AskUserQuestion` ค้างอยู่ หรือ tool ที่ไม่ใช่ agent ค้างเกิน **25 วินาที** → เดาว่าติด permission prompt |
| 💭 thinking | ไม่มี tool ค้าง แต่เทิร์นยังไม่จบ — แสดงพร้อมนาฬิกา |
| ⛔ blocked | เทิร์น**จบ**ลงด้วย error / `hookErrors` / `toolDenialKind` |
| 😴 idle | `stop_reason` ของ Claude เอง (`end_turn`/`stop_sequence`/`max_tokens`/`refusal`) หรือ record สรุปของ Stop hook |

แถว `จบเทิร์นด้วย` บอกว่าใช้หลักฐาน**ตัวไหน** · `blocked` ไม่ค้าง — error เป็น **ประวัติ** ไม่ใช่สถานะ

**สิ่งเดียวที่มันไม่เดา:** หน้าต่างที่ถูกปิดกลางเทิร์นยังทำงานอยู่หรือเปล่า ไฟล์ทะเบียน `session`
**ไม่ใช่ heartbeat** (วัดได้ว่าไฟล์ของ `session` ที่กำลังทำงานอยู่เก่าถึง 274 วินาที) ⇒ "ปิดโน้ตบุ๊กกลางเทิร์น"
กับ "คิดหนักอยู่จริง" แยกจากกันไม่ได้จากข้อมูลที่มี จึงโชว์นาฬิกาให้คนตัดสินเอง แทนที่จะตั้ง timer เดา

`sub-agent` จะถูกตัดสินว่าตายแล้วเมื่อเงียบครบ **180 วินาที** — พร้อมข้อแม้ที่เขียนไว้ในซอร์สเองว่า
ประมาณ 20% ของ `transcript` `sub-agent` จริงเงียบนานกว่านั้น

## แถบโควตา

ในแถบนั้นมีของสองอย่างที่ต่างกัน และมีแค่อย่างเดียวที่ต้องใช้ credential

**แสดงเสมอ ไม่ต้องใช้ credential** — หน้าต่าง 5 ชั่วโมงสด ๆ คำนวณจาก `transcript` ของคุณเอง:
เปิดเมื่อไร รีเซ็ตเมื่อไร มีกี่ request กี่โทเค็นเข้าไป และแยกตาม model ให้ด้วย
ถ้าขอบเขตหน้าต่างมาจาก `resets_at` ของฝั่งบัญชี = ตรงเป๊ะ · ถ้าไม่ใช่ = ประมาณจาก request แรกในหน้าต่าง
และกำกับด้วย `≈` (วัดเทียบกับค่าจริงแล้วคลาดเคลื่อนราว 5 นาที)

**% อย่างเป็นทางการของ Anthropic** (session + รายสัปดาห์):

| โหมด | % มาจากไหน |
| --- | --- |
| ค่าเริ่มต้น | cache ใน `~/.claude.json` ซึ่ง Claude Code เขียนใหม่แค่ตอนสตาร์ตและตอนต่ออายุ token — **เก่าค้างเป็นชั่วโมงได้ หรือผิดไปเลย** |
| `--live-usage` | `GET /api/oauth/usage` รีเฟรชตามรอบที่ตั้ง (ค่าเริ่มต้น 120 วินาที ต่ำสุด 15) |

เมื่อการดึงสดล้มเหลว ตัว poller จะถอยเองตามลำดับ `60s → 120s → 300s → 600s → 900s`
และยืนบนเลขดีตัวล่าสุดไว้บนจอ พร้อมโน้ตว่าเลขนั้นเก่าแค่ไหนและจะลองใหม่เมื่อไร

ตัวเลขต่อ model **ไม่รวม cache read** โดยเจตนา — cache read กินยอดรวมจนกลบส่วนที่เป็นงานใหม่
แต่ต้องรู้ด้วยว่า `cacheRead` คือส่วนใหญ่ของสิ่งที่คุณจ่ายจริง: วัดจาก `transcript` ของ `sub-agent` 634 ตัว
มันคือ ~90% ของทั้งหมดที่ใช้ไป นี่คือเหตุผลที่ input ถูกแยกเป็น 4 ชนิดแทนที่จะรวมเป็นยอดเดียว

## โหมด demo

ทั้งสามหน้าเรนเดอร์ข้อมูลปลอมได้ ทำให้เห็น UI ทั้งหมดก่อนที่จะมีอะไรรันอยู่จริง
**`?fixture` ของหน้าคลาสสิกมีความหมายคนละอย่างกับอีกสองหน้า** และตั้งใจให้เป็นอย่างนั้น

### คลาสสิก

```
http://127.0.0.1:7676/?fixture=45
```

`N` คือจำนวน `sub-agent` ปลอมที่จะวาด — clamp อยู่ในช่วง `1..240` และค่าที่ใช้ไม่ได้จะถอยไปเป็น `45`
มันเรนเดอร์ **ครั้งเดียว** และไม่เปิด event stream เลย จึงไม่มีอะไรเคลื่อนไหว · pill สถานะการเชื่อมต่อ
ขึ้นคำว่า `fixture` จะเข้าใจผิดว่าเป็นข้อมูลจริงไม่ได้

### NEURAL CORE

```
http://127.0.0.1:7676/brain.html?fixture=cascade
```

| ฉาก | เล่นอะไร |
| --- | --- |
| `auto` | วนไปทีละฉากจนครบทุกแบบ (และเป็นค่าที่ใช้เมื่อใส่ชื่อฉากที่ไม่รู้จัก) |
| `idle` | ไม่มีอะไรรันอยู่ |
| `thinking` | คิดนาน ๆ โดยไม่มี tool |
| `cascade` | `sub-agent` แตก `sub-agent` ต่อเป็นทอด |
| `storm` | fan-out ใหญ่ตอนโหลดหนัก |
| `errors` | ความล้มเหลวและการถูก deny |

ฉากพวกนี้ **เคลื่อนไหวจริง** tick ทุก 700 ms และขึ้น toast ว่า
`โหมดข้อมูลจำลอง — ไม่ได้ต่อกับ session จริง` · dropdown `ทดสอบฉาก` ให้สลับฉากได้สด ๆ

ปักคุณภาพการเรนเดอร์เองก็ได้ด้วย `?quality=low|medium|high` และรวมสองอย่างได้:
`/brain.html?fixture=storm&quality=high`

### PIXEL OFFICE

```
http://127.0.0.1:7676/pixel.html?fixture=storm
```

ใช้ชื่อฉากชุดเดียวกับ NEURAL CORE และตัวสร้างข้อมูลจำลองตัวเดียวกัน (`session` ปลอม 2 ตัว · tick ทุก 700 ms) · ชื่อฉาก
ที่ไม่รู้จักถอยไปเป็น `auto` · ฉากพวกนี้ **เคลื่อนไหวจริง**: pill การเชื่อมต่อขึ้น `ต่อแล้ว (จำลอง)` · มีป้าย `ข้อมูลจำลอง`
ข้างชื่อ · ขึ้น toast `โหมดข้อมูลจำลอง — ไม่ได้ต่อกับ session จริง` · dropdown `ทดสอบฉาก` สลับฉากได้สด ๆ · ไม่มี
`?quality` — Canvas 2D ไม่มีอะไรให้ปรับ

## HTTP endpoint

| path | คืนอะไร |
| --- | --- |
| `/api/state` | snapshot JSON ครั้งเดียว พร้อม `cache-control: no-store` |
| `/api/stream` | SSE — ส่ง snapshot ตอนต่อ แล้ว push หนึ่งครั้งต่อการเปลี่ยนแปลง (payload ที่เหมือนเดิมไม่ถูกส่งซ้ำ) |
| `/api/agent?s=<sessionId>[&a=<agentId>]` | รายละเอียดเต็มของ `session` หรือ `sub-agent` หนึ่งตัว — tool input ข้อความ error เหตุผลที่ถูก deny |
| `/` | หน้าคลาสสิก |
| `/<file>` | ไฟล์ static จาก `public/` เท่านั้น |

id ถูกกรองด้วย `/^[A-Za-z0-9_-]{1,64}$/` ก่อนจะถูกนำไปประกอบ path และการเสิร์ฟไฟล์ static
ออกนอก `public/` ไม่ได้ · ไม่มี endpoint ไหนเช็ค HTTP method — `POST /api/state` ได้ snapshot
เหมือน `GET` ซึ่งความเสี่ยงต่ำก็เพราะ server bind แค่ `127.0.0.1`
